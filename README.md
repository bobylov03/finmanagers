# Остатки по кошелькам — MVP

Веб-приложение по ТЗ v1.3: калькулятор фактических остатков денег группы по кошелькам (финцентрам).
Бэкенд — Python (Flask), база — SQLite, интерфейс — HTML + JavaScript без сборки.

## Быстрый старт

Нужен Python 3.10 или новее.

```bash
pip install -r requirements.txt
python run.py
```

Откройте http://localhost:8000. При первом запуске приложение попросит задать пароль администратора (логин `admin`, не короче 8 символов). Дальше порядок первичной настройки виден на экране «Сводка»: загрузить справочники 1С → создать кошельки → правила → пользователи → дата начала учёта → входящие остатки → файл документов → остатки 1С для сверки.

Шаблоны файлов для загрузки скачиваются на экране «Загрузка файлов».

### Через Docker

```bash
docker compose up -d --build
```

База хранится в томе `wallets-data` и переживает пересоздание контейнера.

### На Railway

1. Загрузите проект в репозиторий GitHub и создайте в Railway сервис из этого репозитория — Railway соберёт его по `Dockerfile` (настройки в `railway.json`).
2. Добавьте сервису том (Volume) с путём монтирования `/app/data` — без него база будет теряться при каждом перезапуске.
3. В переменных сервиса задайте `RAILWAY_RUN_UID=0` (контейнер работает не от root, без этого нет прав на запись в том) и `COOKIE_SECURE=1` (Railway открывает приложение по HTTPS). `PORT` Railway задаёт сам.
4. В Settings → Networking нажмите Generate Domain. Оставьте одну реплику: с томом и SQLite больше нельзя.

## Настройки

Задаются переменными окружения или файлом `.env` рядом с `run.py` (образец — `.env.example`).

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT`, `HOST` | `8000`, `0.0.0.0` | Адрес сервера |
| `WALLETS_DB` | `data/wallets.sqlite3` | Файл базы |
| `COOKIE_SECURE` | `0` | `1`, если приложение открывается по HTTPS |
| `SESSION_IDLE_HOURS` | `12` | Через сколько часов бездействия нужно войти заново |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURITY`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` | — | Рассылка уведомлений. Без `SMTP_HOST` и `SMTP_FROM` письма не отправляются |
| `NOTIFY_HOUR` | `19` | После этого часа сервер раз в день рассылает уведомления |
| `MAX_UPLOAD_MB` | `64` | Предельный размер загружаемого файла |

Для работы в сети компании поставьте перед приложением nginx (или другой обратный прокси) с HTTPS и задайте `COOKIE_SECURE=1`.

## Как устроено

```
run.py              запуск (waitress, если установлен; иначе встроенный сервер Flask)
app/server.py       HTTP API, вход, сессии, фильтрация данных по правам, фоновые задачи
app/actions.py      все изменения данных: проверки ТЗ, права, версии документов, журнал аудита
app/importer.py     разбор загрузок 1С: документы, справочники и курсы, остатки для сверки
app/logic.py        расчёт: права и видимость, остатки, сверка, правила автозаполнения, уведомления
app/store.py        SQLite: схема, чтение и запись, неизменяемый журнал аудита
app/mailer.py       рассылка уведомлений по SMTP
static/             интерфейс: index.html, styles.css, js/*.js
tests/              тесты API (unittest) и сквозной тест в браузере (Playwright)
```

**Сервер главный.** Каждое изменение проверяется на сервере: права роли, закрытый период, закрытые кошельки, обязательные поля, курсы. Интерфейс повторяет проверки только для удобства. Сервер отдаёт пользователю только разрешённые ему данные: казначей не получает строки чужих кошельков, скрытые кошельки и чужие остатки 1С. Сверка с 1С и уведомления считаются на сервере по всем данным.

**Один процесс.** Сервер держит рабочую копию данных в памяти и пишет каждое изменение в SQLite в одной транзакции. Поэтому запускайте его в одном процессе (как в `run.py`), без нескольких воркеров gunicorn. Для десятков пользователей и тысяч документов в месяц этого достаточно. На 10 000 документов (20 000 строк) загрузка файла занимает 2–3 с, данные для экрана — около 0,5 с, 1,2 МБ в сжатом виде.

**Загрузка файлов.** Файл .xlsx/.csv читает браузер и отправляет на сервер таблицей значений. Проверку строк, сопоставление по GUID, исключение отсутствующих документов и запись делает сервер.

**Журнал аудита** хранится только в базе. Триггеры SQLite запрещают менять записи и удалять записи моложе 13 месяцев (ТР-46, ТР-47). Удаление всех данных и восстановление из копии журнал не трогают.

**Безопасность.** Пароли хранятся как PBKDF2-SHA256 (240 000 итераций). Сессия — cookie с флагом HttpOnly. После 5 неудачных попыток вход по логину блокируется на 15 минут, все попытки пишутся в журнал. Изменяющие запросы принимаются только с заголовком `X-Requested-With: wallets`, это защита от подделки запросов с чужих сайтов.

**Фоновые задачи** (каждые 10 минут): автозакрытие прошлого месяца 5-го числа (если включено в настройках), очистка журнала старше 13 месяцев, ежедневная рассылка уведомлений, если настроена почта.

### Таблицы базы

Справочники 1С: `orgs`, `accounts`, `cashboxes`, `currencies`, `rates`, `cf_types`, `depts`, `zones`.
Ведутся в приложении: `wallets`, `rules`, `contracts`, `users`, `sessions`, `settings`.
Учёт: `docs` и `doc_lines` (документы 1С и ручной ввод), `ops` (внутренние операции), `opening` (входящие остатки), `bal1c` (остатки 1С для сверки), `versions` (история изменений документов и операций), `closed_changes`, `exchange_log`, `audit`.

## Резервное копирование

- Файл базы: `sqlite3 data/wallets.sqlite3 ".backup backup.sqlite3"` — копию можно делать на работающем сервере.
- Из интерфейса: «Период и настройки» → «Сохранить резервную копию (.json)» и «Восстановить из копии». Журнал аудита при восстановлении сохраняется.

## Тесты

```bash
python -m unittest discover -s tests -v
```

Сквозной тест в браузере (нужны Node.js и Playwright, база должна быть пустой):

```bash
npm i playwright && npx playwright install chromium
WALLETS_DB=/tmp/e2e.sqlite3 python run.py &
node tests/e2e.js http://localhost:8000
```

## API

Все запросы — JSON. Изменяющие запросы требуют заголовок `X-Requested-With: wallets` и сессию (cookie после `/api/login`).

| Метод и путь | Что делает |
|---|---|
| `GET /api/status` | Первый ли запуск, кто вошёл |
| `POST /api/setup` | Пароль администратора при первом запуске |
| `POST /api/login`, `POST /api/logout`, `POST /api/password` | Вход, выход, смена пароля |
| `GET /api/state` | Все данные, разрешённые пользователю, плюс сверка и уведомления |
| `GET /api/version` | Номер версии данных: интерфейс раз в 20 с проверяет, не изменили ли их другие |
| `POST /api/docs/manual` | Поступление на счёт или в кассу, конвертация или переброска (с привязкой внутренней операции) |
| `POST /api/docs/{id}/wallets` | Назначить кошелёк строкам документа |
| `POST /api/docs/{id}/delete` | Пометить ручной документ на удаление или снять пометку |
| `POST /api/ops`, `POST /api/ops/{id}/delete` | Внутренние операции |
| `POST /api/contracts` | Договор займа |
| `POST /api/opening/{счёт}` | Входящие остатки по счёту |
| `POST /api/wallets`, `POST /api/wallets/{id}/close` | Кошельки и перенос остатка при закрытии |
| `POST /api/rules`, `/api/rules/{id}/toggle`, `/api/rules/order`, `/api/rules/apply-empty` | Правила автозаполнения |
| `POST /api/users` | Пользователи и права |
| `POST /api/settings`, `POST /api/settings/close-month` | Период и настройки |
| `POST /api/import/{exp\|ref\|bal}/preview`, `.../apply` | Загрузка документов, справочников и остатков 1С |
| `GET /api/audit`, `POST /api/audit/event` | Журнал аудита |
| `GET /api/admin/backup`, `POST /api/admin/restore`, `POST /api/admin/reset` | Резервная копия, восстановление, очистка |
| `POST /api/mail/send` | Отправить уведомления сейчас |

## Что дальше

- **Шлюз с 1С (ТР-10…13).** Программист 1С может отправлять документы в тот же формат, что и файл: `POST /api/import/exp/apply` с листом строк. Для автообмена нужен отдельный сервисный пользователь или ключ API — это следующий шаг.
- **PostgreSQL.** Вся работа с базой собрана в `app/store.py`. Если пользователей станет больше или понадобится несколько процессов, переход на PostgreSQL сводится к этому модулю.
- **Двухфакторный вход (ТР-48).** Вход сделан отдельным шагом (`/api/login` → сессия), второй фактор добавляется между ними.
